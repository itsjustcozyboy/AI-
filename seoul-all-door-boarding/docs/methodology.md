# 방법론 및 검증 가능한 가설

## 연구 설계

H1: 승차 수요 상위 정류장·시간대에서 실제 승차 처리 대기시간이 길다. 현재 월 집계는 조사 대상을 찾을 수 있으나 H1을 검증하지 못한다.

H2: 앞문 처리 부하가 지배적인 이벤트에서는 뒷문 분산이 체류시간을 줄이지만, 하차가 많은 이벤트에서는 간섭으로 이득이 줄거나 지연이 증가한다. 모형으로 조건을 탐색하며 현장 전후/대조 관측으로 검증해야 한다.

H3: 체류시간 감소가 배차 변동을 줄인다. 운전자의 시간표 보정, 신호, 혼잡, 승객 도착과 차량 간 피드백이 있어 단순 합산으로 증명할 수 없다.

## 수요 정리

CP949로 읽고 모든 ID를 문자열로 보존한다. 24시간 승하차 컬럼을 실제 헤더에서 인식하고 누락·중복 시간쌍을 거부한다. 동일 행만 제거하며 같은 분석키에서 값이 충돌하면 자동 합산하지 않고 실패한다. 음수·무한대·비수치·소수 승객 수는 거부한다. 큰 양수는 실제 수요일 수 있어 임의 절단하지 않는다. 수요 분위수와 누적 집중도를 출력한다.

기본 범위는 간선·지선·순환이며 월 중 노선명/정류장 표기가 다른 행은 보존한다. 물리적 정류장 집계는 표준 ID로 합산한다. ARS는 문자열 그대로 유지하며 미등록·폐지·가상 정류장 여부는 별도 crosswalk가 필요하다. 정류장명은 지도상의 위치 검증 근거가 아니다.

HHI = Σ(노선 내 정류장 승차 비중²). 이는 공간적 집중도이지 체류 지연 지표가 아니다. 피크 시간은 7·8·9·17·18·19시라는 분석 가정이며, 월 합계에 요일이 없으므로 '평일 출퇴근 실측 수요'라고 하지 않는다.

## 문별 체류시간 모형

모든 기본값은 `config/scenarios.yaml`의 임의 가정이다. 서울 관측이나 문헌 보정값으로 표시하지 않는다. 오버헤드 5초, 태그 1.5초/인, 이동 1초/인, 하차 1.2초/인, 도움 발생확률 .02 및 도움 30초/건 등은 오직 탐색용이다. 이동과 태그는 한 문에서 직렬이라고 가정한다.

승차 B, 하차 A, 뒷문 비율 r, 혼잡 가산 c에 대해:

```
front = B(1-r)(tag + front_move)(1+c)
rear_board = Br(tag + rear_move)(1+c)
rear_alight = A * alight_time * (1+c)
conflict = interference * min(rear_board, rear_alight)
dwell = overhead + max(front, rear_alight + rear_board + conflict)
        + assistance_probability * assistance_seconds
```

앞문과 뒷문은 병렬, 뒷문은 하차 후 승차의 직렬 처리다. 고정 시간과 도움 시간은 모든 정책에서 유지한다. 승하차가 전혀 없는 셀은 운행 또는 무정차 여부를 몰라 시뮬레이션 누적 대상에서 제외한다. 함수 자체의 0명 입력은 '정차가 발생한 빈 이벤트'의 오버헤드다.

Scenario 0은 r=0, Scenario 1은 기본 r=.25, Scenario 2는 r=.5다. Scenario 3은 **양의 월 승차 집계 셀의 90분위 이상이면서 지정 피크 시간**인 셀에서만 r=.5를 쓴다. Conservative에서는 실제 사용 비율을 추가로 .6배로 가정한다. 모든 비교는 같은 조건의 Scenario 0과 이루어진다. 음수 절감을 보존한다.

## 월 집계에서 조건부 이벤트 부하로의 변환

```
B = 월 해당 시각 승차 합계 / 해당 월 달력 일수 / 가정 시간당 정차횟수
A = 월 해당 시각 하차 합계 / 해당 월 달력 일수 / 가정 시간당 정차횟수
조건부 일일 절감 = Σ활동셀 [(dwell_0 - dwell_policy) × 가정 시간당 정차횟수]
```

기본 정차횟수는 3·6·12회/시간이며 실측 배차가 아니다. 각 원문 노선명·정류장 표기의 활동 셀에 독립적으로 적용하므로 순환·방향·월 중 개편을 포함한 실제 운행 이벤트 수와 다를 수 있다. 월 모든 날에 균일 운행한다는 가정이다. B/A는 연속 평균량을 사용하는 유체 근사이며 승객을 실제로 분수 명 태운다는 뜻이 아니다. 비선형 max 연산에서 평균 부하의 결과가 개별 이벤트 결과의 평균과 같지 않다.

현재 처리 모형은 승객 수에 대해 구간별 선형이고 모든 정책에서 고정 오버헤드가 같다. 따라서 다른 조건이 같으면 시간당 운행횟수 변화는 이벤트당 절감과 절감률을 바꾸지만 집계 일일 절감은 상쇄될 수 있다. 이것을 운행횟수 가정의 영향이 없다는 실증 결과로 해석하면 안 된다. 정수 승객의 문 선택, 차내 잔여 용량, 동적 혼잡 모형을 보정해야 한다.

표의 조건별 최솟값/최댓값은 설정한 가정들만의 범위다. 모수 불확실성의 확률분포나 95% 신뢰구간이 아니다. 현장 후보는 선택적 정책에서 모든 설정의 최소 절감이 양수인지 확인하고 최소 절감·관측 수요 순으로 정렬한다. 접근성·안전성·단말기 호환성·비용 검토 전 최종 도입 순위가 아니다.

## Plan A/B와 결합

정차 이벤트의 출발-도착으로 초 단위 체류시간을 만든다. 날짜를 포함하므로 자정 통과는 보존하고 음수/600초 초과는 검토용 파일로 분리한다. 600초는 자료 품질 가정이며 장시간 정차를 오류로 확정하는 기준이 아니다.

카드 월 집계와 이벤트는 각각 월·노선·정류장·시간대까지 집계한다. 결합은 one-to-one을 강제하고 outer join 상태를 남긴다. 전체 월 자료와 ID 매핑을 확인하지 않으면 수요-체류 관계 추정을 거부한다. 일부 날짜의 이벤트가 있으면 체류분포와 운행지표만 별도 기술하는 Plan B다.

WLS 종속변수는 집계 평균 체류시간, 독립변수는 해당 집계의 승/하차 합계÷이벤트 수다. 노선·정류장·시간·월 고정효과, 이벤트 수 가중치, 노선 군집 표준오차로 95% 구간을 낸다. 혼잡·신호·날씨·차량·차내 부하는 현 입력에서 통제하지 못한다. 표본 부족·선형종속 설계는 실패한다. 군집 수가 적으면 추론이 부정확하며 인과 효과로 해석할 수 없다. 대규모 고정효과는 dense 설계행렬의 메모리 한계가 있어 분석 범위를 제한해야 한다.

관측 배차간격은 노선·방향·정류장·운행일 내 연속 도착 차이다. 첫 도착에는 간격이 없다. 단일 간격의 표준편차와 CV는 결측이다. 단축/장공백은 그 그룹 중앙값의 .5배 미만/1.5배 초과라는 탐색 기준이다. 예정 배차가 있으면 그 값으로 교체한다. 정책 후 간격은 현재 계산하지 않는다.

## 노선·환경·편익 확장 조건

실제 1회 운행 절감은 trip_id와 정류장 순번을 확인하여 Σ이벤트 절감을 계산해야 한다. 왕복 합산에는 방향과 회차 연결이 필요하다. 누적 초를 차감해 증회·감차를 자동 산출하지 않는다. 배차 시뮬레이션에는 승객 도착, 지연 전파, 신호, 정류장 추월/대기, 종점 회복시간, 홀딩 규칙을 포함하고 별도 검증한다.

환경 계산 함수는 계수·출처를 명시적으로 전달해야 작동한다. 디젤 L/h, CNG kg/h, 전기 보조전력 kWh/h를 구분하고 절감시간 중 실제 에너지 변화가 생기는 비율을 곱한다. 전기버스의 전력 연관 CO2는 배기관 배출과 구분한다. 정차/재가속 횟수 불변이며 지연이 회복 대기로 이동하면 에너지 절감이 없을 수 있다.

차량 초는 승객 초가 아니다. 재차인원·승하차 시점과 대기시간 변화 없이는 승객 시간편익을 화폐화하지 않는다. 비용표는 견적이 없으면 빈 값이다. 단말기와 검표·정산·교육·운영비, 무임승차 변화, 동선 충돌, 이동약자를 함께 평가한다.
